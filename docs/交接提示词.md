# 交接提示词

你接手「AI 审 PRD」项目：一个审查网页，产品经理把 PRD（产品需求文档）粘贴、上传或用链接导入，大模型按 13 条带出处的规则逐条审查，标出问题、给出修改建议，用户可以反馈误判，复核人把采纳的反馈变成评测用例。

## 一、在哪里

- 代码：本机 `~/ai-prd-review-eval`，GitHub `OwenZhao9/ai-prd-review-eval`，分支 main。
- 线上：<https://ai-prd-review.pages.dev>（Cloudflare Pages + D1 数据库，项目名 `ai-prd-review`）。
- 需求文档：`docs/PRD.md`（F1–F30，每条的验收标准就是完成标准）。
- 设计稿：Stitch 项目 <https://stitch.withgoogle.com/projects/12582322962637636600>，导出代码在 `design/stitch/all.html`。配色和字体后来换成 Dribbble「Tetra — Bold Minimalist」风格（黑白灰、左侧导航、大号数字）。`design/` 里其余旧图不用。

## 二、代码结构

- `web/index.html`：整个前端（导入、拆分预览、审查、结果、修改建议、反馈、导出、Word 批注、只读分享、反馈复核、健康看板、接入 GitHub）。
- `web/split.js`：拆分逻辑，网页和 GitHub 合并请求审查共用。`web/convert.js`：Word / PPT / PDF 转成 Markdown，网页和格式评测共用。
- `deploy/src/index.js`：接口（/api/meta、item、suggest、fetch、feedback、feedback/resolve、feedback/export、share、event、metrics、feishu/*）。
- `deploy/build.py`：生成 `deploy/public/`（页面、规则说明、Tailwind 样式 app.css、健康看板数据 dashboard.json、示例 PRD 预算结果 sample.json、_worker.js）和 `deploy/src/prompts.js`。改了 `web/` 或规则后必须重新运行。
- `deploy/github/review-pr.mjs`：GitHub 合并请求自动审查（F29）。
- `app.py`：本机版，和线上共用同一个页面，Python 实现同样的接口，不限额度。`legacy_split.py` 是改版前的拆分，只给 `prd_stats.py` 复算 PRD 里「现状」那几列用。
- 规则在 `rules/`，提示词在 `prompts/`。定版：单句 v4、文档级 doc_v1、账号与权限 module_account_v3，修改建议 suggest_v2。模型 DeepSeek `deepseek-chat`。

## 三、常用命令

```bash
cd ~/ai-prd-review-eval
python3 deploy/build.py                        # 生成页面和提示词
PORT=8788 python3 app.py                       # 本机版
cd deploy && npx wrangler pages dev --port 8799   # 本机跑线上版（出网抓链接会卡，测链接导入用线上）
npx wrangler d1 migrations apply ai-prd-review --remote   # 数据库升级（migrations/ 下新文件）
npx wrangler pages deploy --project-name ai-prd-review --branch main --commit-dirty=true
node split_check.mjs                           # F6–F8 拆分验收 → results/split_check.json
cd data/format && node eval.mjs                # F23 格式一致性 → results/format/
python3 link_check.py https://ai-prd-review.pages.dev   # F3 链接导入验收 → results/link_check.json
python3 suggest_eval.py suggest_v2 evalset,evalset_zh   # F18 修改建议评测（只按开发集调提示词）
```

本机 8788 端口的旧进程用 `kill $(lsof -ti tcp:8788)` 关掉，`pkill -f "python3 app.py"` 匹配不到。

## 四、密钥

- 模型 Key 在本机 `.env`（LLM_API_KEY、LLM_BASE_URL、LLM_MODEL、REVIEW_KEY），`.env` 和 `deploy/.dev.vars` 都不提交。
- 线上用 `wrangler pages secret put LLM_API_KEY / REVIEW_KEY --project-name ai-prd-review` 设置。Key 不许写进代码、日志、提交记录。
- 飞书授权导入要在部署配置里加 FEISHU_APP_ID、FEISHU_APP_SECRET，目前没有配置，需要产品负责人在飞书开放平台建应用。

## 五、硬性规则

- 留出测试集只用来打分，不许照着它的错误改规则或提示词。标准答案的改动写进 `data/adjudication.md`。评测数字必须能从 `results/` 复算。
- 提交：`git -c user.name=owenzhao9 -c user.email=zhaoningup@gmail.com commit`，说明用中文，末尾加一行 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`。每完成一组就提交并推送到 main（仓库已设 `http.version=HTTP/1.1`，大推送不会再断）。推送前确认没有 .env、Key、简历文件。
- 命令自己运行，不要让产品负责人去终端执行。部署、覆盖文件、推送都直接做。
- 不再写 `过程素材/过程记录.md`，测试时不要截图，用页面文字和脚本检查；只有判断视觉效果时才看一眼。
- 界面文字用中文。链接里不要出现 photogif。
- 汇报用中文，结论先行，只说做完了什么、没做什么及原因、需要用户决定什么。

## 六、现状（2026-11-05）

已做完并上线：

- 拆分：表格行转写、代码块不算需求、超长段落按 1500 字分组，158 份样本复算都是 0 违例。拆分预览可以勾选段落、全选、改为审查、编辑和删除需求。
- 审查：三组规则，账号与权限按关键词自动勾选（40 段留出集与评测第 1 次运行有 39 段一致）。每人每天 500 次（部署变量 PER_IP_DAILY 可改），本机缓存，失败重试，额度用完第二天接着审。导入后可以直接审查（⌘/Ctrl+Enter）。

- 修改建议：单条和批量，采用后重新审查；留出集解决率英文 82.6%、中文 79.6%。
