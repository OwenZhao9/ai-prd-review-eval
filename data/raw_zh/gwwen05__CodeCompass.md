## 1. 产品概述 / Product Overview

### 产品名称

**CodeCompass** — 代码理解智能助手

### 一句话介绍

一个基于 Java + Spring AI 的开源代码理解 Agent，帮助开发者用自然语言快速理解任何 Java 项目。

### 解决的问题

开发者在面对陌生的代码库时，普遍面临以下痛点：

1. **信息过载**：一个中型项目可能有几百个类、几千个方法，不知道从哪开始看
2. **调用链不透明**：IDE 只能看单步跳转，难以理解完整的调用链路
3. **业务逻辑分散**：一个业务流程可能跨越多个模块、多个类，手动梳理成本高
4. **缺乏结构化指导**：新人对项目的学习没有路线图，只能随机阅读
5. **文档缺失或过时**：项目文档往往不完整、过时、或根本不存在

CodeCompass 通过 AI Agent 自动分析代码库，将代码转化为可查询的知识图谱，让开发者可以像对话一样理解代码。

## 2. 用户画像 / User Personas

### P1: 小王 — Java 初学者

- **年龄**: 22，应届毕业生
- **技能**: 基础 Java，Spring Boot 基础，无生产级项目经验
- **痛点**: 第一次面对真实项目代码，不知道从哪开始
- **目标**: 理解项目结构，从真实代码中学习
- **使用频率**: 每天使用，作为学习工具
- **核心需求**:
  1. 看到项目的整体结构
  2. 知道先看哪个类、后看哪个类
  3. 用自然语言提问（不懂专业术语）
  4. 获得代码解释（逐行或逐方法）
  5. 生成学习路线

### P2: 老李 — Java 后端开发

- **年龄**: 30，5 年以上经验
- **技能**: 精通 Java，Spring 生态，微服务
- **痛点**: 加入新团队/新项目，需要快速理解大型代码库
- **目标**: 找到特定业务逻辑，理解调用链，评估变更影响
- **使用频率**: 接触新项目时密集使用
- **核心需求**:
  1. 快速搜索特定功能的代码位置
  2. 追踪完整的调用链（上下游）
  3. 理解模块间的依赖关系
  4. 评估代码变更的影响范围
  5. 查找类似的实现模式

### P3: 小陈 — 企业新人

- **年龄**: 25，2 年经验
- **技能**: Java，一些 Spring，参与过小项目
- **痛点**: 入职大公司，代码库庞大复杂
- **目标**: 理解公司的编码模式、业务领域、关键模块
- **使用频率**: 入职前 3 个月每天使用
- **核心需求**:
  1. 理解公司项目的编码规范和模式
  2. 了解业务领域模型
  3. 找到关键入口点（Controller → Service → DAO）
  4. 获得结构化的入职学习路径
  5. 能够就具体代码提问

### P4: 张 Tech Lead — 架构师

- **年龄**: 35，10 年以上经验
- **技能**: 系统架构，多语言，团队领导
- **痛点**: 需要评估项目质量、识别技术债务
- **目标**: 快速架构概览、依赖分析、代码质量洞察
- **使用频率**: 项目评审时使用
- **核心需求**:
  1. 项目整体架构可视化
  2. 模块依赖合理性分析
  3. 循环依赖检测
  4. 关键质量指标（耦合度、复杂度）
  5. 代码审查辅助

## 3. 用户故事 / User Stories

### P1: Java 初学者

1. **作为** Java 初学者，**我想要** 输入一个项目路径就能看到项目结构概览，**以便** 我能知道这个项目由哪些模块组成
2. **作为** Java 初学者，**我想要** 用自然语言提问（"登录功能在哪？"），**以便** 我不需要知道确切的类名就能找到想要的功能
3. **作为** Java 初学者，**我想要** 获得一个"推荐阅读顺序"，**以便** 我能按正确的依赖关系学习代码
4. **作为** Java 初学者，**我想要** 看不懂的代码能被逐行解释，**以便** 我能从项目中学习编码技巧
5. **作为** Java 初学者，**我想要** 看到方法之间的调用关系图，**以便** 我理解代码是如何协作的

### P2: Java 后端开发

1. **作为** 后端开发，**我想要** 用关键词搜索代码（类名、方法名、注释内容），**以便** 我能快速定位相关代码
2. **作为** 后端开发，**我想要** 追踪一个方法的完整调用链（谁调用了它，它调用了谁），**以便** 我理解修改的潜在影响
3. **作为** 后端开发，**我想要** 理解一个业务场景涉及的完整代码路径（Controller → Service → Repository → DB），**以便** 我能进行正确的修改
4. **作为** 后端开发，**我想要** 分析修改一个类会影响哪些其他类，**以便** 我能评估改动的风险
5. **作为** 后端开发，**我想要** 对比两个类似功能的实现方式，**以便** 我能选择最佳的修改方案

### P3: 企业新人

1. **作为** 企业新人，**我想要** 获得一个针对新人的代码学习路径，**以便** 我能快速上手工作
2. **作为** 企业新人，**我想要** 了解项目的编码规范和常见模式，**以便** 我写的代码能与项目保持一致
3. **作为** 企业新人，**我想要** 理解项目的业务领域模型（什么是 Order、什么是 Product），**以便** 我能理解业务需求和技术实现的映射
4. **作为** 企业新人，**我想要** 看到项目的 API 文档自动生成，**以便** 我知道有哪些接口可以调用
5. **作为** 企业新人，**我想要** 就具体代码段提问并获得带上下文的回答，**以便** 我不需要频繁打扰同事

### P4: 架构师

1. **作为** 架构师，**我想要** 看到模块之间的依赖图，**以便** 我能快速评估系统架构
2. **作为** 架构师，**我想要** 检测循环依赖和不合理的依赖方向，**以便** 我能识别架构问题
3. **作为** 架构师，**我想要** 了解关键质量指标（行数、圈复杂度、耦合度），**以便** 我能识别需要重构的代码
4. **作为** 架构师，**我想要** 分析第三方依赖的使用情况，**以便** 我能管理依赖风险
5. **作为** 架构师，**我想要** 对代码库进行"健康检查"，**以便** 我能制定技术改进计划

## 4. 功能需求 / Functional Requirements

### FR1: 仓库分析 (Repository Understanding)

| 属性 | 值 |
|------|-----|
| 优先级 | **P0** |
| 描述 | 解析 Java 项目结构，包括 Maven/Gradle 模块、包结构、类关系 |
| 验收标准 | ① 能解析多模块 Maven/Gradle 项目 ② 输出模块依赖树 ③ 输出包结构树 ④ 统计类、方法、字段数量 |

### FR2: 代码搜索 (Code Search)

| 属性 | 值 |
|------|-----|
| 优先级 | **P0** |
| 描述 | 支持全文搜索、正则搜索、语义搜索三种模式 |
| 验收标准 | ① 关键词搜索返回文件路径+行号 ② 正则搜索支持复杂模式 ③ 语义搜索支持自然语言 ④ 搜索结果按相关度排序 |

### FR3: 调用链图 (Call Graph)

| 属性 | 值 |
|------|-----|
| 优先级 | **P0** |
| 描述 | 构建方法级和类级调用关系图，支持上下游追踪 |
| 验收标准 | ① 构建方法级调用图 ② 查询"谁调用了X" ③ 查询"X调用了谁" ④ 支持 N 层深度追踪 |

### FR4: 业务理解 (Business Understanding)

| 属性 | 值 |
|------|-----|
| 优先级 | **P1** |
| 描述 | 提取业务逻辑，构建领域模型，分析业务流程 |
| 验收标准 | ① 识别 Service 层业务方法 ② 提取领域实体 ③ 追踪完整业务流程链路 ④ 输出业务流程文档 |

### FR5: 学习路径 (Learning Path)

| 属性 | 值 |
|------|-----|
| 优先级 | **P1** |
| 描述 | 根据代码依赖关系生成推荐阅读顺序 |
| 验收标准 | ① 识别项目入口点（main、核心 Controller） ② 按依赖关系排序 ③ 生成分步学习计划 ④ 支持角色定制（新人 vs 熟手） |

### FR6: 代码问答 (Code QA)

| 属性 | 值 |
|------|-----|
| 优先级 | **P1** |
| 描述 | 通过自然语言向代码库提问，获得带代码引用的答案 |
| 验收标准 | ① 支持多轮对话 ② 答案包含具体代码引用 ③ 支持追问和澄清 ④ 回答质量可评估 |

### FR7: RAG 引擎

| 属性 | 值 |
|------|-----|
| 优先级 | **P0** |
| 描述 | 检索增强生成，将相关代码片段作为 LLM 的上下文 |
| 验收标准 | ① 代码分块策略 ② 向量化和索引 ③ 相似度检索 ④ 上下文窗口管理 |

### FR8: 记忆系统 (Memory)

| 属性 | 值 |
|------|-----|
| 优先级 | **P1** |
| 描述 | 持久化存储对话历史、用户偏好、项目知识 |
| 验收标准 | ① 会话内上下文保持 ② 跨会话记忆恢复 ③ 长对话自动摘要 ④ 项目分析结果缓存 |

### FR9: 多 Agent 编排 (Multi-Agent)

| 属性 | 值 |
|------|-----|
| 优先级 | **P2** |
| 描述 | 多个专业 Agent 协作完成复杂分析任务 |
| 验收标准 | ① 至少 3 种专业 Agent ② Agent 间可通信 ③ 任务可委派 ④ 结果可聚合 |

### FR10: 工作流引擎 (Workflow)

| 属性 | 值 |
|------|-----|
| 优先级 | **P2** |
| 描述 | 可配置、可编排的 Agent 工作流 |
| 验收标准 | ① YAML/JSON 定义工作流 ② 顺序和并行执行 ③ 错误处理和重试 ④ 工作流可视化 |

### FR11: MCP 支持

| 属性 | 值 |
|------|-----|
| 优先级 | **P3 (未来)** |
| 描述 | 支持 Model Context Protocol，作为 MCP Server 提供服务 |
| 验收标准 | ① 实现 MCP 协议 ② 注册 Tools ③ 暴露 Resources ④ 兼容主流 MCP 客户端 |

## 5. 非功能性需求 / Non-Functional Requirements

### 性能

| 指标 | 目标 |
|------|------|
| 100 个类的项目解析 | < 30 秒 |
| 1000 个方法的调用图构建 | < 5 秒 |
| 单次搜索响应 | < 2 秒 |
| RAG 回答生成 | < 10 秒（不含 LLM 延迟） |
| 首次项目索引（1000 类） | < 5 分钟 |

### 可靠性

- 错误处理：所有外部调用（LLM API、数据库）必须有重试机制
- 降级策略：LLM 不可用时，至少保留搜索和图查询功能
- 数据一致性：分析结果应支持校验和版本管理

### 安全性

- API Key 管理：不在日志中打印、不在代码中硬编码
- 代码隐私：默认本地处理，用户可选择是否发送代码到外部 LLM
- 输入验证：对所有用户输入进行验证和清洗

### 可维护性

- 模块化设计：各模块通过接口通信，可独立开发和测试
- 文档覆盖：所有公共 API 有 Javadoc
- 测试覆盖：核心逻辑 > 80%，关键路径 > 90%

### 可扩展性

- 语言扩展：通过 SPI 支持解析多种语言（Java 优先）
- LLM 提供商：通过 Spring AI 支持多个 LLM 提供商
- 存储后端：通过接口抽象，支持多种数据库
- MCP 生态：预留 MCP 协议扩展点

### 可用性

- CLI 优先：第一版只提供命令行界面
- 错误友好：错误信息清晰，给出解决建议
- 反馈及时：所有操作给出进度提示

- ✅ 全文搜索

**核心功能**：调用链图 + 业务分析

**核心功能**：多 Agent 协作 + 学习路径

## 8. 约束与假设 / Constraints & Assumptions

### 技术约束

1. 必须基于 Java 17+
2. 必须使用 Spring Boot + Spring AI
3. 必须支持 Maven 构建
4. 第一阶段仅支持 Java 语言分析

### 业务约束

1. 开源项目，Apache 2.0 许可证
2. 可作为 CLI 工具独立运行，也可作为库嵌入
3. 第一篇目标：单机运行，不依赖云服务

### 假设

1. 用户分析的代码库遵循标准的 Java 编码规范
2. 用户有基本的命令行操作能力
3. LLM API 在开发和测试期间可访问
4. 项目初期只有一名开发者

## 9. 术语表 / Glossary

| 术语 | 英文 | 说明 |
|------|------|------|
| Agent | Agent | 能够使用工具、自主决策的 AI 组件 |
| RAG | Retrieval-Augmented Generation | 检索增强生成：先检索相关文档，再交给 LLM 生成回答 |
| MCP | Model Context Protocol | 模型上下文协议：标准化的 AI 工具交互协议 |
| 调用图 | Call Graph | 方法/函数之间调用关系的方向图 |
| 知识图谱 | Knowledge Graph | 代码实体（类、方法、字段）及其关系的图 |
| 工作流 | Workflow | 编排多个 Agent 按顺序或并行执行任务 |
| 嵌入 | Embedding | 将文本转换为向量表示 |
| 分块 | Chunking | 将长文本分割为适合检索的小段 |
| SPI | Service Provider Interface | Java 服务提供者接口：插件式扩展机制 |
