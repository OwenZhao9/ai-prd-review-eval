# MD 阅读器小程序 PRD

> 文档版本：v1.5  
> 文档状态：已确认  
> 确认日期：2026-07-16  
> 产品形态：微信小程序  
> 暂定名称：MD 阅读器  
> MVP 目标：让用户在微信聊天中方便、可靠地阅读 Markdown 文件

## 1. 产品概述

MD 阅读器是一款面向微信聊天文件的 Markdown 阅读小程序。

用户收到 `.md` 文件后，可在微信文件页面选择“用 MD 阅读器打开”；小程序读取文件并渲染标题、列表、表格、代码块等 Markdown 内容，同时提供目录、搜索、代码复制、阅读样式调整和 PDF 导出发送能力。

当微信没有展示小程序打开入口时，用户也可以进入小程序，主动从聊天记录中选择 Markdown 文件。

## 2. 背景与问题

微信可以接收和下载 `.md` 文件，但缺少适合 Markdown 的原生阅读体验。用户直接打开时，常见问题包括：

- Markdown 标记未被渲染，阅读效率低。
- 长文档缺少目录和快速跳转。
- 代码块缺少高亮和复制操作。
- 表格、任务列表等内容难以阅读。
- 用户通常需要把文件转发到电脑或其他应用处理。

微信官方提供“聊天素材支持小程序打开”能力，并明确支持 `text/markdown` 类型，因此可以通过小程序补足这一体验。

## 3. 产品目标

### 3.1 MVP 目标

- 用户可以从微信聊天文件进入小程序并阅读 `.md` 文件。
- 用户可以在小程序内从聊天记录选择 `.md` 文件作为备用入口。
- 常见 Markdown 内容能够准确、稳定、安全地渲染。
- 长文档、技术文档和代码内容具备明显优于纯文本的阅读体验。
- 产品功能价值足以支撑微信小程序审核，而不只是简单文件预览。

### 3.2 成功指标

MVP 体验版阶段使用以下指标验证产品：

| 指标 | 目标 |
| --- | --- |
| 合法 Markdown 文件打开成功率 | 不低于 95% |
| UTF-8 文件解析成功率 | 不低于 99% |
| 500 KB 文档首屏渲染时间 | 主流手机不超过 1.5 秒，不含微信下载时间 |
| 打开失败时的可理解提示覆盖率 | 100% |
| 核心流程崩溃率 | 低于 0.5% |

具体性能目标在首轮真机测试后校准。

### 3.3 非目标

以下能力不纳入 MVP：

- 不承诺点击文件后自动默认进入本小程序。微信仅提供“用小程序打开”入口，最终选择权由用户和微信客户端控制。
- 不提供完整 Markdown 编辑器。
- 不提供多人协作、评论或版本管理。
- 不提供账号体系和跨设备同步。
- 不提供 Word、图片或 HTML 等其他格式转换。
- 不依赖服务端上传和解析文件。

## 4. 目标用户与场景

### 4.1 目标用户

- 在微信中接收 AI 生成 Markdown 内容的普通用户。
- 需要在手机上查看 README、接口文档或技术说明的开发者。
- 通过微信传递课程笔记、方案和知识库内容的学生及职场用户。

### 4.2 核心场景

**场景 A：从聊天文件打开**

1. 用户在微信聊天中收到并下载 `.md` 文件。
2. 用户打开文件页面并选择“用 MD 阅读器打开”。
3. 小程序读取文件并展示渲染结果。
4. 用户通过目录、搜索和阅读设置浏览内容。

**场景 B：从小程序主动导入**

1. 用户进入 MD 阅读器小程序。
2. 用户点击“打开聊天文件”。
3. 用户从聊天记录中选择一个 `.md` 文件。
4. 小程序读取并展示渲染结果。

**场景 C：导出并发送 PDF**

1. 用户在阅读页点击“PDF”。
2. 小程序在本地将当前 Markdown 分页生成 PDF。
3. 小程序调起微信文件发送面板，用户选择好友发送。
4. 当前微信版本不支持直接发送时，小程序打开 PDF，用户从右上角菜单转发。

## 5. 微信平台约束

- 小程序需在 `app.json` 的 `supportedMaterials` 中声明 `text/markdown`。
- 从聊天素材打开时，启动场景值为 `1173`，文件信息由 `forwardMaterials` 提供。
- 小程序配置必须审核通过并正式发布，相关入口才会对正式用户展示。
- 用户通常需要先使用过该小程序，微信才会在对应素材的打开方式中展示它。
- “自动打开”或“设为微信默认 Markdown 应用”不属于小程序可控制能力。
- 体验版和正式版的 `supportedMaterials` 配置相互独立，需要分别验证。
- 仅提供简单预览可能被微信认为功能价值不足，提交审核时需突出目录、搜索、代码处理及阅读优化等能力。

## 7. 详细功能需求

### 7.1 聊天素材打开

**需求说明**

- 小程序声明支持 `text/markdown`，打开文案暂定为“用 MD 阅读器阅读”。
- 小程序启动或重新唤起时检查场景值和 `forwardMaterials`。
- 接收到多个素材时，仅处理第一个合法 Markdown 文件，并提示其余文件暂未打开。
- 新文件进入时，若当前已有文档，直接切换至新文件并清理上一次临时状态。

**验收标准**

- 体验版可通过场景值 `1173` 完成模拟调试。
- iOS 和 Android 微信中均能从聊天文件进入正确阅读页。
- 冷启动和热启动均能获得正确文件信息。
- 参数缺失或文件已失效时，不出现白屏或无限加载。

### 7.2 主动选择聊天文件

**需求说明**

- 首页提供醒目的“打开聊天文件”主操作。
- 调用微信聊天文件选择能力，默认只接受单个文件。
- 选择非 `.md` 文件时拒绝读取，并说明当前仅支持 Markdown。
- 用户取消选择时保持当前页面，不展示错误提示。

**验收标准**

- 用户最多三步即可从小程序首页打开一份聊天中的 Markdown 文件。
- 取消、无权限和选择失败均有正确状态处理。

### 7.3 文件读取与校验

**需求说明**

- MVP 默认支持 UTF-8 和带 BOM 的 UTF-8 文件。
- 文件扩展名应为 `.md`，同时结合传入 MIME 类型进行判断。
- 512 KB 以上提示可能影响性能；超过 1 MB 暂不读取。
- 采用渐进渲染优先展示首屏，避免一次向视图层传输完整长文档。
- 读取过程展示稳定的加载状态，不因加载文字变化导致页面布局跳动。
- 文件读取失败时保留“重新选择文件”和“返回首页”操作。

**异常文案类型**

- 文件不存在或临时路径已失效。
- 当前文件不是 Markdown 文件。
- 文件过大，暂时无法打开。
- 文本编码暂不支持。
- 文件读取失败，请重新选择。

### 7.4 Markdown 解析与渲染

**P0 支持语法**

- 六级标题、普通段落和换行。
- 粗体、斜体、删除线和行内代码。
- 有序列表、无序列表、嵌套列表和任务列表。
- 引用、链接、图片和水平分隔线。
- 围栏代码块及语言标记。
- GFM 表格。
- `$...$` 行内公式和 `$$...$$` 块级公式。

**渲染规则**

- 默认禁用 Markdown 中的原始 HTML，避免脚本和危险标签执行。
- 对生成内容进行白名单过滤，不渲染脚本、内联事件或危险 URL。
- 表格、代码块和超宽块级公式允许横向滚动，不压缩到无法阅读。
- 公式语法错误时显示原始 LaTeX，单个公式不得导致整页加载失败。
- 超长标题、链接和连续字符必须换行或滚动，不得撑破页面。
- 文档中的绝对网络图片按微信域名和下载规则处理。
- 相对图片路径因聊天入口通常只传入单个 `.md` 文件，MVP 显示占位和说明，不承诺自动找到附件。
- 外部链接 MVP 提供复制地址操作；是否允许直接跳转由微信平台规则和业务域名配置决定。

### 7.5 目录与阅读定位

**需求说明**

- 根据 H1-H4 自动生成分级目录。
- 阅读页提供目录按钮，点击后从侧边展示目录。
- 点击目录项滚动到对应标题，并关闭目录面板。
- 当前阅读章节在目录中高亮。
- 再次打开最近文档时恢复上次阅读位置和所在章节。

**验收标准**

- 200 个标题以内目录可正常生成和跳转。
- 重复标题也能定位到各自正确位置。
- 无标题文档不显示目录入口。

### 7.6 文档内搜索

**需求说明**

- 支持输入关键词并显示匹配结果总数。
- 支持上一个、下一个结果跳转。
- 搜索不区分英文字母大小写。
- 清除搜索后恢复正常阅读状态。
- MVP 搜索正文文本，不搜索图片内容。

### 7.7 代码块体验

**需求说明**

- 根据围栏后的语言标记进行语法高亮。
- 未知语言使用普通等宽文本展示。
- 每个代码块提供复制按钮和复制成功反馈。
- 长代码行横向滚动，禁止自动缩小字号。
- 大型代码块不得阻塞整个文档的首屏展示。

### 7.8 阅读设置

**需求说明**

- 支持浅色、深色和跟随系统三种主题模式。
- 支持至少三档字号和三档行距。
- 设置保存在本地，下次打开继续生效。
- 主题切换后正文、代码、表格、引用和弹层均保持足够对比度。

### 7.9 首页和空状态

**首页内容**

- 产品名称。
- “打开聊天文件”主操作。
- 最近打开列表：默认展示 3 条，点击“查看全部”后在固定高度区域滚动浏览全部记录。
- 点击记录可重新打开文档；支持删除单条记录和一键清空全部记录。
- 单条删除前默认显示确认弹窗；用户可勾选“以后不再确认”，确认删除后在本机持久保存该偏好。
- 删除操作只移除小程序保存的本地副本，不影响微信聊天中的原文件。
- 设置入口。

首页直接服务于打开文件，不制作营销式落地页，不展示冗长使用说明。

### 7.10 PDF 导出与发送

**需求说明**

- 阅读页工具栏提供紧凑的“PDF”操作，仅在文档就绪时可用。
- PDF 使用 A4 纵向分页，保留文件名、标题、正文、列表、引用、代码块、表格、分隔线和页码。
- 导出过程完全在设备本地完成，不上传 Markdown 正文或 PDF。
- 单次最多导出 60 页，生成文件最大 20 MB；超出时给出明确提示，不继续分享。
- 生成成功后优先调用微信文件发送面板；接口不可用或非用户取消的发送失败时，打开 PDF 并显示右上角转发菜单。
- 导出期间展示页数进度并禁用重复操作；用户主动取消发送后不再次弹出其他分享流程。
- 行内和块级数学公式按实际排版结果写入 PDF，覆盖分式、根号、上下标、求和、AMS 环境和 `\text{}`；单个公式解析失败时回退显示可读 LaTeX 源码。
- 网络图片以替代文字占位；后续版本再评估图片下载与高保真导出。

**验收标准**

- 中英文文档可生成能被微信打开的合法 PDF。
- 行内和块级公式在 PDF 中显示排版结果，不暴露 `$`、`$$` 或 LaTeX 命令；错误公式仍保持可读。
- 生成文件名沿用 Markdown 文件名并替换为 `.pdf`，非法文件名字符被安全替换。
- 支持直接选择微信好友发送；不支持直接发送的环境可从 PDF 右上角转发。
- 导出失败、页数超限、文件过大或微信版本不兼容时均有可理解提示。


## 9. 非功能需求

### 9.1 性能

- 解析和渲染应避免长时间占用主线程。
- 文档按固定块数渐进传给视图层，大文档优先保障首屏可见，再补充后续内容。
- 搜索输入需防抖；滚动时不得重复测量全部标题位置。
- 工具栏、目录和加载状态使用稳定尺寸，避免内容加载时发生明显跳动。

### 9.2 稳定性

- 所有文件读取、解析和渲染过程必须有异常捕获。
- 单个不受支持的 Markdown 节点不得导致整页白屏。
- 冷启动、热启动、前后台切换和重复打开文件均需测试。

### 9.3 隐私

- MVP 不上传 Markdown 正文、文件路径或代码内容。
- 埋点只记录文件大小区间、打开来源、耗时和错误码。
- 最近打开会在小程序用户目录保存成功解析的本地副本，最多 20 条、合计最多 50 MB，不上传正文。
- 导出的 PDF 使用原 Markdown 文件名并替换为 `.pdf`；同名文档后续导出直接覆盖。
- 删除单条记录或清空记录时同步删除对应本地副本，不影响微信聊天中的原文件。
- 首页启动时清理历史目录中未被元数据引用的孤立副本。
- 隐私政策需要明确说明本地文件读取用途和数据处理方式。

### 9.4 安全

- 禁止执行 Markdown 中的 HTML、JavaScript 和内联事件。
- 限制 `javascript:`、`data:` 等危险链接协议。
- 网络图片加载失败不得影响正文阅读。
- 复制操作必须由用户主动触发。

### 9.5 兼容性

- 首发验证最新正式版微信的 iOS 和 Android 客户端。
- 开发者工具只作为基础验证，聊天文件入口必须完成真机测试。
- 对不支持聊天素材入口的旧客户端保留小程序内主动选择文件的能力。
- 对不支持 `wx.shareFileMessage` 的客户端使用 `wx.openDocument({ showMenu: true })` 作为发送兼容路径。

## 10. 数据与埋点

MVP 建议记录以下匿名事件，不包含文档正文：

| 事件 | 关键字段 |
| --- | --- |
| `file_open_start` | 入口来源、文件大小区间 |
| `file_open_success` | 入口来源、解析耗时、渲染耗时 |
| `file_open_fail` | 入口来源、错误码、文件大小区间 |
| `toc_open` | 标题数量区间 |
| `search_use` | 是否有结果，不记录关键词 |
| `code_copy` | 代码语言，不记录代码内容 |
| `reading_setting_change` | 设置项和选项 |

在尚未配置合规的数据服务前，可先使用本地调试日志，不接入线上埋点。

## 11. 技术方案约束

### 11.1 小程序配置示意

```json
{
  "supportedMaterials": [
    {
      "materialType": "text/markdown",
      "name": "用${nickname}阅读",
      "desc": "阅读、搜索和浏览 Markdown 文档",
      "path": "pages/reader/index"
    }
  ]
}
```

最终 `name` 和 `desc` 需根据小程序实际名称、平台字数限制及审核要求调整。

### 11.2 建议处理链路

```text
微信聊天素材 / 主动选择文件
        -> 文件参数校验
        -> 本地读取与编码处理
        -> Markdown 解析为结构化节点
        -> 安全白名单过滤
        -> 小程序组件渲染
        -> 目录、搜索、代码高亮增强
```

### 11.3 技术原则

- 第一版采用微信原生小程序，降低文件入口和生命周期调试复杂度。
- Markdown 解析器优先选择成熟、维护活跃且包体积可控的实现，不自行编写完整解析器。
- 渲染层不得直接信任解析器生成的任意 HTML。
- 核心阅读流程离线可用，不把服务端作为必需依赖。

- [ ] 单条删除和一键清空同步删除本地副本，不影响聊天原文件。

### 12.2 Markdown 样例

- [ ] 中英文混排文档。
- [ ] 标题、嵌套列表、引用和分隔线。
- [ ] GFM 表格、任务列表和删除线。
- [ ] 多种语言代码块及超长代码行。

### 12.3 体验质量

- [ ] 深浅主题下正文、代码和数学公式均清晰可读。

### 12.4 PDF 导出

- [ ] 中文、英文和混排文档导出的 PDF 可正常打开，分页和页码正确。
- [ ] 标题、列表、引用、代码块和表格内容完整，无裁切或重叠。
- [ ] 行内公式基线正确，块级公式居中；分式、根号、上下标、求和、AMS 环境和中文 `\text{}` 均正确渲染。
- [ ] 直接文件发送可选择微信好友，用户取消后不继续打开 PDF。

## 14. 主要风险与应对

| 风险 | 影响 | 应对方案 |
| --- | --- | --- |
| 小程序未出现在文件打开列表 | 用户无法走最短路径 | 确保用户先使用过小程序；检查体验版配置、客户端版本和审核状态；保留主动选文件入口 |
| 审核认为功能过于简单 | 无法正式发布入口 | MVP 同时提供目录、搜索、代码高亮、复制及阅读设置，并准备完整审核说明 |
| 大文件导致卡顿或白屏 | 核心体验失败 | 设置大小限制、分阶段处理、降级代码高亮并进行真机压力测试 |
| Markdown 方言差异 | 部分内容显示错误 | 明确支持 CommonMark/GFM 范围，建立兼容样例库 |
| 原始 HTML 带来安全风险 | 内容注入或异常跳转 | 默认禁用原始 HTML并执行节点及 URL 白名单过滤 |
| 相对图片无法读取 | 文档图片缺失 | MVP 明确提示限制，后续研究多文件导入或压缩包方案 |
| 非 UTF-8 文件乱码 | 阅读失败 | MVP 给出明确提示，P1 增加编码检测和转换 |
| PDF 导出占用内存过高 | 低配置手机卡顿或生成失败 | 逐页栅格化并及时删除临时图片，限制 60 页和 20 MB，完成 Android/iOS 真机压力测试 |

## 15. 评审结论

以下事项已于 2026-07-16 确认，并作为 MVP 开发基线：

- [x] 产品暂定名称使用“MD 阅读器”。
- [x] MVP 坚持完全本地处理，不建设服务端。
- [x] 目录、搜索、代码高亮、复制和阅读设置全部作为首发 P0。
- [x] 首发只支持 UTF-8，其他编码放入 P1。
- [x] Mermaid 保持 P1，避免拖慢首次发布。
- [x] 根据视图层数据放大测试，将提醒阈值收紧为 512 KB、硬限制收紧为 1 MB；多 MB 文件需待更深层虚拟化后再开放。
- [x] 最近打开保存受数量和容量限制的本地副本以支持冷启动重开，正文不上传。
- [x] PDF 作为 P0 本地导出能力，优先直接发送微信好友，并保留打开后转发的兼容路径。
- [x] PDF 中的数学公式使用本地矢量渲染，解析失败的单个公式降级为 LaTeX 源码。
- [x] 产品面向普通用户，技术文档阅读作为重点场景但不限定人群。
