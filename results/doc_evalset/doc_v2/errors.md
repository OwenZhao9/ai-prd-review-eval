**功能描述**:
作为专业用户，我想要系统自动检查内容合规性，以便避免法律风险和行业规范违反。

**用户价值**:
- 消除合规风险
- 节省人工检查时间
- 提升内容专业性

**功能逻辑与规则**:
1. **行业规范自动遵循**:
   - 政府文件：遵循公文格式规范

   - 金融报告：满足监管披露标准
   - 医疗内容：遵循医疗广告法规

2. **敏感内容实时拦截**:
   - 政治敏感词汇自动标记
   - 医疗宣称用词自动校正
   - 金融承诺表述风险提示
   - 版权内容使用合规检查

3. **法律术语自动校正**:
   - "治愈率" → "缓解率"
   - "保证收益" → "预期收益"
   - "根治" → "改善"
   - "绝对安全" → "相对安全"

4. **学术文献校验**:
   - 影响因子自动查询
   - 引用格式标准化
   - 数据来源可信度评估

**交互要求**:
- 实时高亮问题内容
- 提供修改建议和替代方案
- 显示合规检查进度和结果

**数据需求**:
- 行业规范数据库
- 敏感词库和替换词典
- 法律法规条文库
- 学术期刊数据库

**技术依赖**:
- 文本分析和NLP技术
- 规则引擎和知识图谱
- 实时数据库查询

**验收标准**:
- 敏感内容检出率 ≥ 99%
- 误报率 ≤ 5%
- 检查响应时间 ≤ 3秒
- 法律术语校正准确率 ≥ 95%

## DDJ5  标准：['D3']  预测：无问题
> #### Session Deep Link（跨平台会话导航）

iOS 与 Android 共享同一个只读导航协议：`opencode://session/<session_id>`。链接可以来自 Chat 中的 Agent Markdown，也可以来自邮件、Notes、网页或系统 Intent。用户点击后，客户端只在当前 Host 调用 `GET /session/:id` 验证；成功才切换到目标 session 和 Chat，失败保留原上下文并显示全局错误。

Android cold start 与 warm launch 都支持该协议。连接尚未恢复时保存最后一个 pending link，连接成功后再解析。目标 session 不要求已进入当前 100 条列表窗口；验证成功后把完整 Session 注入列表，保证 Chat、Files 和 workspace Markdown link 使用目标 `directory`。

Session 搜索继续由 Agent 和 semantic-search 负责，客户端不建设搜索页面、embedding 索引或离线 archive 读取能力。V1 不自动切换 Host，不携带 Host Profile、server URL、凭证、query 或绝对路径，不支持 message 定位（链接可携带 message_id，打开后自动滚动到该消息），也不能发送 prompt、批准权限、执行 tool、删除或归档 session。

- 漏判：['D3']

## DE05  标准：无问题  预测：['D1', 'D2']
> #### Ambient Mode（对齐 iOS，2026-10-17）

设置默认关闭。打开后，手机和专注布局出现静态波形入口，展开布局在内容栏切换到同一页面。用户在前台自己开始。连接尚未完成时离开前台会取消；已经在听或说时可以保持。应用不会自动重开这场语音。

语音走 Hosted Builder 全双工：PCM16 单声道 24 kHz，采集按设备采样率重采样。静音是 48dp 胶囊，填充跟随输入 RMS；控制行高 72dp；播放音量使用系统通话音量。

工具限于八个：查询会话、读取消息、开始、继续、停止、回答待处理、归档、解除归档。开始和继续在服务端接受请求后即返回，不等待任务跑完。归档带上子会话；解除归档把归档时间写成 0。过期或不再属于当前 owner 的调用会被拒绝。结束这场语音不会中止已经交给 OpenCode 的任务。

麦克风前台服务只在用户已经开始、并且界面可见时启动。服务先进入前台并确认，然后才采集。被拒绝的启动不会卡在前台启动超时上。通知里的停止会等音频收干净再撤下前台服务。

页面上的费用是本地标准价估算，与最近一次门户用量快照分开。会议记录、sleep，以及 question/permission 的新主动通知不在这次范围内。
- 误判 D1：「段落描述了 Ambient Mode 的开关、入口、语音链路、工具集、前台服务等，但没有任何验收标准或可直接检查的具体结果（如「连接未完成时离开前台会取消」没有可判定的完成条件，工具调用「被拒绝」没有可检查的返回或状态）。」整段只有功能描述，缺少可判定做完/做对的验收条件或具体可检查结果。
- 误判 D2：「「被拒绝的启动不会卡在前台启动超时上」「过期或不再属于当前 owner 的调用会被拒绝」只说明会被拒绝，但未说明拒绝后系统如何处理（如提示、状态回退、重试），也未覆盖连接失败、采集失败等主要失败情况。」涉及权限/状态变化与外部服务调用，但主要失败情况的处理方式未说明。

## DE06  标准：无问题  预测：['D1', 'D2']
> #### Phase 7：Markdown Web Preview 与平板 Sessions 折叠（对齐 iOS PR #94/#95）

本阶段补齐两个 iOS 已落地能力。第一，Files 中的 Markdown 预览从单一路径升级为 Native / Web / Source 三态。Web Preview 负责承载 AI internal writing 里已经开始使用的 HTML/CSS 卡片、inline SVG、深浅色语义变量和折叠审计层；Native Preview 保留为稳定回退；Source 用于调试和大文件安全查看。

产品边界：`.md` / `.markdown` 文件提供 Web Preview（默认）、Native Preview、Markdown Source 三种模式。Web Preview 支持 HTML-in-Markdown 的安全子集（局部 `<style>`、`div/span` 卡片、inline SVG、`details/summary`、GFM 表格）。workspace 相对图片复用 `MarkdownImageResolver.resolveImages(...)` 转 data URI。大文件先显示确认 gate。WebView 只加载 app assets 里的 renderer shell，不从网络加载 JS，不直接读取 workspace 文件系统。`<script>`/`iframe`/`form`/`on*`/`javascript:` 被禁止。深浅色主题下正文、卡片、代码块、chip 保持可读。

第二，平板三栏布局的左侧 Sessions pane 支持折叠。展开时保持当前 25% / 37.5% / 37.5% 三栏；折叠时左栏不渲染，Files 与 Chat 平分宽度；Files 顶栏左侧显示展开按钮。这个能力只作用于 tablet / expanded width，不改变手机底部 Tab 和 session sheet 逻辑。
- 误判 D1：「段落描述了 Web Preview 三态、安全子集、图片转 data URI、大文件确认 gate、Sessions 折叠等，但没有任何验收标准或可直接检查的具体结果（如三态切换后的具体状态、折叠后宽度比例如何验证、安全过滤的判定结果）。」功能点均未给出可判定做完/做对的具体结果或验收标准。
- 误判 D2：「Web Preview 涉及文件读取、图片解析、WebView 加载与安全过滤，但段内未说明渲染失败、图片解析失败、大文件确认取消、WebView 加载出错等失败情况如何处理。」涉及文件读写与外部渲染，缺少主要失败情况的处理方式。
