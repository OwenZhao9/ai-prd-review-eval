# doc_v2 漏判与误判

## DH01  标准：['D1']  预测：['D1', 'D2']
> ### 8.3 用户体验验收
- 用户界面友好易用
- 配置过程简单明了
- 帮助文档完整详细
- 一键启动功能正常

**详细标准**:
- **界面友好性**: 系统需要提供友好易用的用户界面，确保用户能够快速理解和使用各项功能。界面设计需要符合用户体验设计原则。

- **配置简便性**: 系统需要提供简便的配置过程，最小化用户的配置工作。配置过程需要提供清晰的指导和帮助。

- **文档完整性**: 系统需要提供详细的使用说明和故障排除文档，帮助用户快速上手和解决问题。文档需要包括安装指南、使用教程、常见问题、故障排除等。

- **启动便捷性**: 系统需要支持一键启动功能，用户能够通过简单的操作启动所有功能。启动过程需要自动化，减少用户的操作复杂度。
- 误判 D2：「「一键启动功能正常」「启动过程需要自动化」等处未说明启动失败、部分功能启动失败或配置出错时系统如何处理」一键启动涉及状态变化与可能的失败，段内未给出任何失败情况的处理方式。

## DH02  标准：无问题  预测：['D2']
> ### US-06 处理 AI 建议

作为使用者，我希望检查建议后选择接受、修改或拒绝。

验收标准：

- Suggestion 显示来源 Capture 版本。
- Capture 已更新时明确标记建议过期。
- 接受标题、Content Type 或 Category 必须是显式操作。
- 接受标题或 Content Type 时复用 Capture 修订规则并增加版本；只接受 Category 时不增加正文版本。
- 摘要和语义单元保留在 Suggestion 中，不替换原文。
- 勾选局部原文建议时，实时显示基于已保存版本的整篇修改前/修改后对比，确认前不写回。
- 最近一次 accepted/modified Suggestion 保存采纳前快照；没有后续 Capture 修改、AI 分类变化或候选主张推进时，允许整体回退并生成新的 Revision。
- 整体回退恢复标题、正文、Content Type 和 AI 分类，删除本次新建且仍为 candidate 的主张；保留手动分类、Suggestion 和版本历史。
- 每个 Suggestion 只允许完成一次最终决策。
- 误判 D2：「段落描述了接受/修改/拒绝建议、写回与整体回退等状态变化，但未说明操作失败（如保存失败、版本冲突、回退失败）时系统如何处理」功能涉及状态变化和写回操作，段内没有对主要失败情况给出处理方式。

## DH05  标准：['D1', 'D2']  预测：['D2']
> ### 3.5 GW — API 网关

API 网关让外部系统以标准协议接入 AI 能力，核心价值是在接口转发之外提供记忆注入与技能增强。v1.6 起默认提供「纯净转发」模式（关闭领域模式时不注入不记录），记忆注入与技能增强需开启网关领域模式。

- **GW-1 多协议入站**：
  - **OpenAI Chat Completions**：`POST /v1/chat/completions`，支持流式/非流式/函数调用/视觉。
  - **OpenAI Responses**：`POST /v1/responses`，支持推理模型。
  - **Anthropic Messages**：`POST /v1/messages`，Claude 系列协议。
  - **Google Gemini**：`POST /v1/gemini/...`，Gemini 系列协议。
  - **Ollama 原生**：`POST /api/chat` `/api/generate` `/api/tags` 等，伪装 Ollama 服务供 Ollama 兼容客户端直接调用。
  - **图像生成 API**：`POST /v1/images/generations`，支持文生图。
  - **图像编辑 API**：`POST /v1/images/edits`，支持编辑修复。
  - **模型发现 API**：`GET /v1/models`，可用模型列表。
  - **嵌入向量 API**：`POST /v1/embeddings`（OpenAI 兼容）。
  - **语音 API**：`POST /v1/audio/speech` 语音合成、`POST /v1/audio/transcriptions` 语音识别（OpenAI 兼容）。
  - **视频生成 API**：`POST /v1/video/generations` 任务式提交 + `GET /v1/video/generations/{taskId}` 状态查询。
  - **重排序 API**：`POST /v1/reranks`（DashScope 兼容格式）。

- **GW-2 认证与路由**：
  - **AppKey 认证**：`sk-` 前缀随机密钥，每个 AppKey 绑定用户身份、模型范围。
  - **模型路由**：根据模型编码选择服务商和模型。
  - **上游 429 指数退避重试**：带随机抖动，最多 5 次。
  - **网关领域模式**：关闭时网关作为纯净 LLM 网关仅转发流量（鉴权/限流/配额/用量，不记录对话、不注入用户信息）；开启时启用完整处理器链（记忆/技能注入）并自动记录对话，与 Web 对话能力对齐。
  - **用户隔离**：向 LLM 服务商透传 User 字段（Web=用户ID，网关/渠道=AppKey.UserId），用于服务商侧 KV-Cache 隔离。

- **GW-3 用量记录**：
  - **用量记录**：每次调用记录 Token 消耗、耗时等指标，同时归属到用户与 AppKey 双维度。
  - **基础用量统计**：按日聚合，支撑用户和 AppKey 维度查询。
- 漏判：['D1']

## DH15  标准：无问题  预测：['D1', 'D2']
> ### FR-4 G-code 改写引擎（Python 脚本逻辑的移植 + 修复）

将现有脚本的四类改写移植为 TypeScript 模块，并修复已知问题：

1. **喷嘴温度（修复硬编码，见 FR-8）**：改写开机段中等于"源打印温度"的 `M104/M109 S<t>` 行 → 目标温度；同步改配置头 `nozzle_temperature`、`nozzle_temperature_initial_layer`。开机段固定流程温度（170/140/250 等预热、擦嘴温度）不动。
2. **Z 偏移**：改写 `G29.1 Z… ; for Textured PEI Plate` 行。若找不到该行（非 Textured PEI 床型），列入安全检查警告并说明后果，而不是静默跳过。
3. **流量倍率**：在打印主体 `;VT0` 后注入/替换 `M221 S<flow>`；同步改配置头 `filament_flow_ratio`。
4. **移动速度**：主体内独立 `G1 F<n>` 行 → `G1 F<speed×60>`；行内 `F30000` token → 同值替换。
5. **改写标记**：在 gcode 头部注入一行处理标记（如 `; allyoucanseal: processed v<version> params=<json>`），用于防重复处理（FR-6）和溯源。
6. **md5 同步**：改写后重算并更新 3mf 内对应的 `.gcode.md5` 文件（当前脚本的已知缺陷）。
7. 引擎必须是纯函数式的（输入文本+参数 → 输出文本+变更报告），与 UI 解耦，便于单元测试。
- 误判 D1：「整个 FR-4 段落列出了 7 项改写要求，但没有任何验收标准或可直接检查的具体结果（如改写后温度值、Z 偏移量、M221 值、速度换算结果、md5 是否匹配等均无判定条件）」段落只描述要做什么，缺少可判定做完/做对的具体结果或验收标准。
- 误判 D2：「第 2 项仅说明找不到 G29.1 行时列入警告，但第 1、3、4、6 项（温度行、VT0 后注入、G1 F 行、md5 重算）均未说明找不到目标行、格式不符、md5 计算失败等失败情况如何处理」功能涉及文本解析与文件读写，主要失败情况缺少统一处理说明。

> ### 2.2. 查找相似剧集 (`get_similar_shows`)
*   **用户故事:** 作为一个刚看完一部很喜欢的美剧的用户，我希望可以告诉 LLM 这部剧的名字，以便它能给我推荐几部风格或主题相似的其他剧集。
*   **功能需求:**
    *   MCP Server 需暴露一个名为 `get_similar_shows` 的工具。
    *   工具接受一个参数：`show_title` (剧集名称，字符串)。
    *   服务器首先需要通过 `show_title` 调用 TMDb API 找到对应的剧集 ID。**决策：如果找到多个同名剧集，默认选择第一个结果。如果找不到，返回明确的错误文本。**
    *   服务器使用剧集 ID 调用 TMDb API 的"查找相似"功能。
    *   服务器处理并格式化返回的相似剧集列表，**默认返回 10 部**。**决策：返回格式需包含剧名、年份、评分和简介。**
- 误判 D2：「服务器使用剧集 ID 调用 TMDb API 的"查找相似"功能。」段落未说明调用 TMDb 查找相似接口失败（网络错误、超时、无结果）时系统如何处理，只覆盖了查找剧集 ID 阶段的失败。
