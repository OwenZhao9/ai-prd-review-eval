数据来源：

- 示例 PRD 是开源项目 caesarloo/obsidian-svn 的需求文档（MIT 许可），审查结果来自 `deploy/public/sample.json`。
- 07–09、11 的段落数、需求条数、调用次数，用 `python3 design/counts.py` 算出，结果在 `results/design_counts.json`。
- 15、16、22、37、51：改写是为演示改完再审写的。改写后的审查结果是 2026-11-05 在线版（单句规则 v4、文档级规则 doc_v1）实际返回的结果，存在 `results/design_rereview.json`（51 用的是其中的 round2：把「支持与最新版本的差异对比」改成「必要时支持与历史版本的差异对比」）。
- 45 改为审查后多出的 2 条需求，是按现有拆分规则从示例 PRD「1. 背景与目标」段拆出的。
- 50 用 2026-11-02 那条反馈演示驳回后的样子，这条反馈实际是被采纳的。
- 20、21 的反馈来自 `data/feedback.jsonl`。
- 23、38 的数字来自 `results/*/metrics.json`；38 里各规则的 F1 用 `python3 design/counts.py` 算出，在 `results/design_counts.json` 的 dashboard_per_rule。
- 33 的段落和审查结果来自 `data/module_account_holdout.jsonl` 和 `results/module_account_holdout/module_account_v3/predictions_run1.jsonl`（AH06、AH07、AH08）。
- 23、38 里写「—」的指标，数值由 F26（多数表决）、F23（格式一致性）、F27（多人标注一致率）的评测和第 7 节的埋点（线上使用）填入。
- 25–28、31、34、37 画的是进行中、失败、筛选、已提交这些状态，画面里的条目和审查结果沿用示例 PRD 的真实数据；31 里取消勾选 4.6，是为了画出「未审查」的计数；28、37 的失败是演示失败时的样子。
